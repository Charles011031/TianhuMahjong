# 🀄 天胡麻将馆 · 计时收费系统

给澳洲麻将馆柜台用的记账系统：**6 张桌计时收费、零食饮料、鸭嘴兽、会员储值、员工打卡工资、营业统计**。
一个网址打开就用，手机 / 平板 / 电脑多设备实时同步，断网也能继续记，还能装成手机 App。

| 项目 | 当前 |
|---|---|
| **正式网址** | **[https://charles011031.github.io/TianhuMahjong/](https://charles011031.github.io/TianhuMahjong/)** ← 唯一在维护的地址 |
| **形态** | 单个网页（约 90 万字符）+ Firebase 实时数据库 + PWA |
| **旧地址** | Google Apps Script 表格版（脚本 `v30`），**2026-10-13 起冻结**，只做兜底 |

**当前版本**：`v3.30.4`（2026-10-30）—— 页面左上角标题旁、页面最底部各显示一处。

> 数据在 **Firebase 云端**，不在浏览器里 —— 换设备、清缓存都不会丢。
> 但反过来：**网址就是写入口**，别发群、别发朋友圈、别放进公开仓库。

---

## ⚠️ 先看三件事

1. **多设备可以同时用，但别同时改同一样东西。**
   开台、挂零食、打卡这些谁看到谁操作都行；但同一张桌的结算 / 改时间 / 取消，
   尽量只在一台设备上做 —— 两台同时改，后写的会覆盖先写的。
2. **数据在云端，但备份仍然要做。**
   每天打烊点一次「备份/恢复 → 下载备份文件」，把 JSON 存到网盘 / 微信收藏。
   Firebase 免费额度和安全规则都由账号决定，别把唯一副本押在云端。
3. **改完代码必须走发布流程。**
   不要只改 `mahjong-timer.html` 就以为线上变了 —— 线上是 GitHub Pages 上的
   `部署/index.html`，要用 `工具/发布.py` 生成 + 测试 + 推送，并且**等线上真的返回新版本**再刷新。

## 🚀 快速开始

### 1. 打开

浏览器（Chrome / Edge / Safari 现代版本）打开：

**https://charles011031.github.io/TianhuMahjong/**

就这样，不用装软件、不用登录。刷新页面会**停留在你当时那一页**。

### 2. 第一次用：先设四项

| 设置 | 默认 | 说明 |
|---|---|---|
| **每小时价格** | `16` | 所有桌台统一（澳币/小时） |
| **手续费** | `1.2%` | **只对刷卡收**，向上取整到分 |
| **汇率** | 自动 | 澳币→人民币；每天 6 点后自动刷一次，也可手改 |
| **营业日起算** | `08:00` | 早于这个时间算**前一天**（晚班凌晨的收入不会算错天） |

- 汇率默认按「市场价 × (1 + 0.33%)」模拟支付宝价（加点可改，见 [全局设置](#settings)）
- 其它设置（时薪、忙日、提成、充值档位）在对应页面里，见 [设置](#settings)

### 3. 每天的收银主线

```
客人来了 → 桌台页点「▶ 开始计时」
         → 中途点了零食饮料 → 「挂到桌台」（会自动扣库存）
         → 客人要走 → 「⏹ 结束计时」（默认现在，可改回实际离开时间）
         → 桌台变「待结算」→ 慢慢核对 → 「💰 结算收费」
         → 选收款方式（可分开付 / 按人分账 / 罚款 / 会员余额）
         → 确认结算 → 记录进结算记录，可随时编辑
```

- 客人打完直接走、还没收钱？先把表停了，桌子空出来给下一桌，回头再结（见 [自助场景](#selfservice)）
- 记错了随时改，见 [编辑记录](#record-edit)

## 📱 装成手机 App（PWA）

| 手机 / 设备 | 步骤 |
|---|---|
| **iPhone / iPad** | 用 **Safari** 打开网址 → 点底部「分享」⬆️ → 「添加到主屏幕」 |
| **Android** | 用 Chrome 打开 → 右上角 ⋮ → 「安装应用」 |
| **Mac / Windows** | Chrome / Edge 打开 → 地址栏右侧的 ⊕ 安装图标 |

装好后桌面出现「**天胡**」图标，点开全屏无地址栏，页签状态也保留。

**关于离线**：网页本身会被 Service Worker 缓存（网络优先，保证拿到最新版），
所以断网时一般还能打开、还能继续记账，联网后自动补传。
但 Firebase SDK 走的是 Google CDN —— **从来没有联网打开过的新设备，第一次不能纯离线用**。

## 🧭 系统总览

### 数据怎么走

```
   手机 / 平板 / 收银电脑
          │  HTTPS 打开网页
          ▼
   GitHub Pages 上的 index.html（单文件网页，含界面 + 全部业务逻辑）
          │  ←→ 本机缓存（localStorage，离线时先记本机）
          │  Firebase SDK：WebSocket 实时同步（<1 秒）
          ▼
   Firebase Realtime Database（项目 tianhu-fd795，新加坡）
   shops/<路径密钥>/
     records      结算记录        snacks       零食饮料
     vapes        鸭嘴兽          memberRows   会员充值流水
     attendance   员工打卡        inventory    商品库存
     employees    员工名单        stockLogs    盘点记录
     tableStates  桌台状态        settings     系统设置
     pending      待结算          reservations 预约
          │
          │  独立定时任务，每 15 分钟只读拉一次
          ▼
   Google 表格「天胡麻将馆 · 实时版数据」（12 个工作表，看图表用，不参与记账）
```

### 网页是怎么来的（三种文件，别搞混）

| 文件 | 是什么 | 能不能手改 |
|---|---|---|
| `mahjong-timer.html` | **唯一源文件**（含 Google 表格同步层），所有功能都在这里改 | ✅ 只改这一个 |
| `mahjong-timer-firebase.html` | 由源文件**生成**的 Firebase 版（同步层换成 Firebase，业务逻辑零改动） | ❌ 生成物，会被覆盖 |
| `部署/index.html` | 线上发布物（由 Firebase 版去掉模板语法生成） | ❌ 生成物，会被覆盖 |

> 以前的 Google Apps Script 表格版（`网页版/`）**已经冻结**（2026-10-13 起只发 GitHub 版）。
> 老网址打开的是旧版界面 + **旧 Google 表格里的数据**，和现在的 Firebase 数据**不互通**，
> 只能当兜底，**不要再用它记账**。

## 🀄 桌台计时

<a id="billing"></a>

### 计费规则

- 每小时价格**统一**（页面顶部设置），默认 `$16/小时`
- 按**分钟向上取整**：不足 1 分钟按 1 分钟
- 台费 = 向上取整到分（费率 × 小时）；**手续费只对刷卡收**，也向上取整到分（跟 Excel 的 ROUNDUP 一样）
  - 例：`$2 + 手续费 = $2.03`（2 × 1.012 = 2.024 → 进位）

<a id="states"></a>

### 桌台状态

| 状态 | 含义 | 能做什么 |
|---|---|---|
| **空闲** | 没在用 | ▶ 开始计时（整行大按钮）/ ⏱ 自定义时间补录 / 有欠款时 🧾 补收 $X / ＋ 挂零食 |
| **计时中** | 正在打 | ⏹ 结束计时 / ⏸ 暂停 / 🔄 换桌；小号：📄 看账单、⏱ 改时间、✖ 取消计时 |
| **已暂停** | 暂停中不计费 | ▶ 继续 / ⏹ 结束计时 / 🔄 换桌；小号同上 |
| **待结算**（橙色） | 表已停、钱还没收 | 💰 结算收费 / 📄 看账单 / ⏱ 改时间 / ↩ 撤销结束 / ✖ 取消计时 |

**待结算区（独立列表）**：收进待结算的桌会在这里排一排，桌子可以直接给下一桌用。
每张卡有「💰 结算收款 / 📄 看账单 / ✎ 改零食 / ↩ 搬回 X 号桌 / ✕ 删掉」。

- 计时中 / 暂停中 / 待结算卡：**那一行右侧有淡灰小字「＋ 挂零食」**，点一下直接切到零食页并预选该桌
- 空闲桌也有「＋ 挂零食」：客人先到、人没齐还没开台，可以先把饮料挂上，开台后一起结
- 桌卡右上角有「备注」输入框，可以写「等朋友 / 换桌原因」
- 有欠款时桌卡会显示红色角标「**上次未付 $X**」

<a id="selfservice"></a>

### 自助场景（客人打完直接走）

推荐流程：**先「结束计时」定结束时间 → 再慢慢加零食 → 最后「结算收费」**

1. 员工看到桌还在跑，点 **⏹ 结束计时**
2. 把结束时间改成客人实际离开的时间（默认现在）
3. 点「**⏹ 结束计时（稍后再结算）**」→ 桌台变「待结算」，数字冻住
4. 这时可以去零食页把东西**挂到这张桌**
5. 回来点「**💰 结算收费**」

> 记录日期按**营业日**算（见 [营业日说明](#bizday)），凌晨打的会算到前一天。

<a id="settle"></a>

### 结算弹窗

1. **怎么收？** 四个快捷按钮：💵 现金 / 💳 刷卡 / 🇨🇳 人民币 / 🎫 会员余额 —— 点一个整桌都按它收。
2. 要每人不同方式 → 点「▸ 分开付 / 多人各付各的」，每个号位单独选「怎么付」。
3. **👥 台费 4 人分**：台费一键分 4 笔（打麻将 AA 常用），零食仍然单独算。
4. **⚖️ 罚款**：填金额（按台费算，跟着台费一起平摊；会员余额也能抵）。
5. 还可以「+ 加一笔」「👥 按人分账」「⋯ 更多选项（其它费用 / 合并结算另一桌 / 平分 / 一人全付）」。

**四种收款方式**

| 方式 | 金额 | 手续费 | 备注 |
|---|---|---|---|
| **刷卡** | ✏️ 可改 | **+1.2%**（向上取整） | 默认方式；可填「实收（含手续费）」反推本金 |
| **现金** | ✏️ 可改 | 无 | 可抹零 |
| **人民币** | ✏️ 可改 | 无 | 另填「实收 ¥」，改澳币时 ¥ 自动重算；有「📄 看人民币账单」 |
| **会员扣款** | ✏️ 可改 | 无 | 需选会员；**只能抵台费，不能抵零食饮料** |

**两条硬规则**

1. **会员余额只能抵台费**（含「上次未付」）；整单里如果还有零食，那部分**自动拆出来**另收现金/刷卡/人民币
2. 会员扣款总额超过台费时，**实时黄字警告 + 确认时拦截**

**整单收款时「应收」跟着付款方式走**（v3.25.0）

| 付款方式 | 「应收」显示 | 小字 |
|---|---|---|
| 刷卡 | 账单 + 手续费（例 `$28.08`） | 含手续费 $0.34 |
| 人民币 | 折成人民币（例 `¥130.41`） | ≈ $27.74 澳币 |
| 现金 | 账单金额 | 实收填低了显示「抹零 −$3.74，实收 $24.00」 |
| 会员余额 | 账单金额 | 会员抵台费、零食另付 |

<a id="split"></a>

### 按人分账

适合「一桌人各付各的」：

- 填「几人」（1～12），点号位 = 给这个人加 1 份零食；某样零食 3 份 = 3 个号位各点一下
- **台费谁付**不选就是各付各的；勾「**台费+零食合并一笔**」则把自己的台费份额和零食合成一笔
- **应收 / 实收实时更新**，每行显示「已分 2/2 ✓」自动校验有没有分完
- 分好后点「填入收款明细」，再回整单确认
- 「**⌨ 表格填写（旧版）**」保留老的分账输入方式；「**💰 高级：按笔改金额**」可逐笔微调
- 会员收款也能直接搜会员（整单和按人分账同一套搜索）

<a id="short"></a>

### 欠款 / 上次未付（分次结算）

- 结算时「明细合计 < 应收」→ 可以选：
  - **记在这张桌上，下次一起结**（$1 以上默认这个）
  - **直接免除（抹掉，不算欠）**（$1 以内默认这个）
- 记下的欠款会在桌卡上显示红标签「上次未付 $X」，**下次结算自动加进应收**
- **换桌时欠款跟着搬**（目标桌本来也欠着钱的，两笔相加）

<a id="records"></a>

### 三个结算记录列表（同一个标准）

桌台计时 / 零食饮料 / 鸭嘴兽 页下方各有一个结算记录列表，**长相和排序完全统一**：

| 页面 | 列数 | 说明 |
|---|---|---|
| **桌台计时** | 8 列 | 时间（开台–结束）｜桌号｜时长｜台费｜零食｜应收｜收款｜操作 |
| **零食饮料** | 6 列 | 时间｜品项｜小计｜应收｜收款｜操作 |
| **鸭嘴兽** | 6 列 | 时间｜品项｜小计｜应收｜收款｜操作 |

**共同点**

- **按日期分组**，标题行：`📅 2026-10-06 周二 · 6 笔` + **右侧当天小计**
- **排序**：日期从新到旧；同一天内按时间从晚到早（补录老日期的账会归到那天的组里）
- **收款是彩色小色块**：刷卡=蓝 / 现金=绿 / 人民币=橙 / 会员扣款=紫；会员扣款会写扣谁的
- **额外的钱写在「应收」下面小字里**（零食手续费 / 抹零、鸭嘴兽刷卡加价、桌台含手续费）
- 数字列右对齐，金额为 0 的格子显示灰色 `—`
- 📱 手机上自动变成「一笔一张摘要卡」，一屏能看 4～5 笔

<a id="record-edit"></a>

### 编辑结算记录

每条记录都有 **编辑**，可以完整改（**和重新结算一样**）：桌号、开始/结束时间、其它费用、收款明细。

| 按钮 | 作用 |
|---|---|
| **平分台费** | 把台费平均分到几笔上（保留各笔原方式）；零食饮料单独一笔 |
| **台费按 4 人分** | 台费一键分 4 笔 |
| **♻️ 当作重新结算** | 丢掉旧分账，从「一笔 = 全部合计」重新开始 |
| 全部走现金 / 全部走刷卡 | 保留金额，只改付款方式 |

**刷卡可以直填实收（含手续费）**

- 填了实收 → 本金自动反推（`实收 $42.10` → 本金 `$41.60`，手续费 $0.50）
- 留空 → 回到自动按 1.2% 算
- 手动改本金 → 实收也跟着重算

**几个细节**

- 打开时会**自动还原**成收款明细（老记录也能还原出会员那笔）
- 改时间 → 台费重算 → 明细跟着等比调整（手动改过金额后就不再自动调）
- **会员余额自动对账**：先把原来扣的还回去，再按新金额扣
- 日期按**营业日**算（凌晨的账仍归前一天）

<a id="cancel"></a>

### 取消计时（防误触开台）

### 预约（v3.26.0 改版）

**桌台页顶部「今天待来」提醒条**（只显示今天还没到店的）：

- 一行看全：今天几场、下一场几点、还有多久；**30 分钟内变黄、超时没到变红**
- 点开可以「到店开台 / 取消」——**到店会自动给这桌开台**，并把客人名字写进备注
- 处理完的那条从条上消失，变成「已到 1」的小计

**下面「📅 预约台账」**（全部预约，不折叠）：

- 表单：日期 / 时间 / 姓名 / 电话 / **人数** / 桌号 / 备注，**姓名和电话至少填一个**
- 分「今天 / 明天以后 / 过期待处理」三组；每条显示谁录的、多久前录的、备注全文
- 同一张桌同一时段（±90 分钟）已有预约时，**保存前会红字拦一下**，再点一次「仍要添加」才保存
- 「📜 历史」：查最近 30 天的预约（搜姓名 / 电话 / 日期）
- **当日收工后自动收起**：今天的预约全部处理完（没有待来）**并且**所有桌台都已结清（没有计时中 / 暂停 / 待结算）时，顶部提醒条和台账里的当日预约都不再显示，只留明天以后；只要还有一张桌在用或还有待来的预约，就照常显示
- 有预约的桌，卡片上会显示提醒；**明天的预约也会显示「明天 20:00 陈先生」**

**📝 客服录入（`网址#cs`）**：

- 客服收藏带 `#cs` 的链接（或微信浮窗），打开就是整屏录入界面，看不到桌台 / 结算 / 会员
- 客人微信原话粘进去 → 自动识别时间 / 人数 / 电话；桌号用大按钮选，橙色表示该时段已有预约
- 保存后自动生成一段**确认话术**，客服复制粘贴回客人微信（**不会自动发消息**）
- 录完店里所有设备**弹大字卡片 + 响铃 + 震动**；点「收到，已安排」才消失，其他设备上的同一条一起收起
- 「📅 客服录入」按钮也能进（右上角可切回完整系统）

## 🍜 零食饮料

### 商品菜单（卡片式）

- **零食左 / 饮料右**，各一个限高框，**框内自己滚**（商品再多也不会把页面撑很长）
- 每张卡片：**照片**（没照片显示 emoji）｜商品名｜单价｜库存
- **点卡片 = 加一份**；点过的卡片底部变成 **「− N ＋」**，减到 0 自动移出点单
- 顶部 tab：**全部 / 🍿 零食 / 🥤 饮料**；搜索框**商品名和分类都能搜**
- **库存为 0** 的卡片灰掉、显示「售罄」，点不进去
- 右上角：**📋 盘点记录** / **✎ 编辑**；卡片上有「盘点」按钮
- 右上角 **⠿** 按住可拖动排序（在本分类里，只改本机显示顺序）

### 点单（购物车）

- 面板里能看到选了啥：缩略图、名字、单价、库存、小计；**− / ＋ 改数量、✕ 删除**，超过库存会拦
- 手机上面板自动换成两行，按钮加大好点
- 右下角**悬浮购物车**（`已选 N 件 · 应收 $X`），点一下直接跳到结算按钮并闪一下
- **加购反馈**：卡片角标弹一下 + 手机震动

### 统一编辑（照片 / 名称 / 单价 / 库存 / 加商品 / 删商品）

点右上角 **✎ 编辑** → 弹出全部商品列表，所有修改都在这里做：

| 想改什么 | 怎么做 |
|---|---|
| **商品照片** | 点每行左边 📷 → 选图 → 拖动 / 缩放裁剪 → 存成 200×200 小图 |
| **删除照片** | 点照片右上角 ✕ |
| **名称 / 单价 / 库存** | 直接在那一行改 |
| **加商品** | 最上面 **＋ 快速添加**（回车也行，可以连着录好几个） |
| **删商品** | 行尾 ✕ → 标记删除 → 点 **保存** 才生效 |

- 平时菜单里**改不动**（防手滑），点 **✎ 编辑** 才进得来
- 编辑过程中**不写数据**，点 **保存** 才生效；**取消** 就什么都不变

### 库存

- **点单不能超过库存**：点卡片加购、点单里的 ＋ 都会被拦；库存调小时超量部分自动夹回
- **结算 或 挂到桌台 都会自动扣库存**
- 「清除」桌台零食 或「取消计时」→ 库存**自动还回**
- 桌卡上「✎ 编辑」可改挂桌零食的数量 / 删掉某样 → 库存自动扣 / 还（待结算区也有「✎ 改零食」）

### 盘点（库存校准）

每张卡片库存旁有「盘点」按钮：

```
盘点 · 零食 可乐
系统里记的库存：20
实际数量：[18]
→ 差异 -2（盘亏，库存扣掉这些）
```

确认后库存直接改成实际值，并留一条记录。标题栏 **📋 盘点记录** 能看最近 30 条。

### 三种出账方式

1. **单独结算** → 可改结账日期（默认按营业日）
2. **挂到桌台** → 并入该桌的「其它费用」，跟台费一起收
3. 点单里的 **✕** → 单独删掉一项

**挂到桌台（v3.25.0 改版）**

- 先点「**挂到桌台**」页签，下方出现**桌台卡片**：状态（计时中 / 待结算 / 未开台）+ 台费或已打时长 + 已挂金额
- **未开台的桌也能挂**（客人先到、人没齐、还没开始计时）
- 选好桌后下方写着「已选 X 号桌（状态）→ 该桌已挂 $Y → 挂后 $Z」，点 **✓ 确认挂账** 直接挂上（无二次确认）
- 挂账金额 = **小计，不含手续费**；手续费在结算该桌时按付款方式算
- 挂完提示条带「**去看 X 号桌**」；挂错了在桌卡「✎ 编辑 / 清除」改，库存自动退回

### 历史记录可编辑

结算记录每行有 **编辑**：可改日期、时间、品项、小计、支付方式、应收（可抹零）、实收人民币。

## 🦆 鸭嘴兽

> 以前叫「电子烟」，2026 年起统一改名 **鸭嘴兽**（页签、记录、导出表都用这个名字）。

### 价格设置（页面顶部两栏）

```
阶梯价  按同代总根数算             员工价与刷卡
─────────────────────────────    ────────────────────────────
🟢 一代  零售$[40] 满3根$[38] 满5根$[36]   员工价  一代$[35]／根  二代$[35]／根
🟣 二代  零售$[45] 满3根$[43] 满5根$[40]   刷卡    加价$[5]  ⦿每根 ○每单
```

- **阶梯按一二代合计的总根数**算（例：2 根一代 + 1 根二代 = 3 根 → 两代都按满 3 根价）
- **满 10 根再打八折**（按零售价 × 0.8，自动生效，不用设置）
- 勾选「**员工价**」→ 忽略阶梯，两代各按自己的员工价算（结算后自动取消勾选）
- 选**刷卡**：价格 ＋ 加价，**再算 1.2% 手续费**

### 口味与库存（卡片式）

- 顶部 tab：**全部 / 🟢 一代 / 🟣 二代**（tab 上带数量）
- **一代在左（绿）/ 二代在右（紫）**，卡片显示照片 / 口味名 / 当前单价 / 库存
- **点卡片 = 加一根**；点过的卡片变成 **「− N ＋」**，减到 0 自动移出点单
- **阶梯价自动显示**：点单合计到 3 / 5 / 10 根时，卡片单价自动变折后价并标出档位
- **库存为 0** 灰掉显示「售罄」；卡片有「盘点」按钮
- 右上角 **⠿** 拖动排序；**📋 盘点记录** / **✎ 编辑**（改代别 / 口味名 / 库存 / 照片）
- 右下角悬浮购物车（`已选 N 根 · 应收 $X`）

### 收款

- 支付方式：**人民币（默认）/ 现金 / 刷卡**；人民币可改澳币应收（¥ 自动重算），现金可抹零
- **只能当场结算，不能挂到桌台**（没有挂账入口）

### 历史记录可编辑

和零食一样，可改日期、时间、品项、小计、刷卡加价、支付方式、应收。

## 💰 会员充值

### 新增会员

- **姓名不能重复**；重名**必须填电话**区分；电话填了也不能和别人重复
- 列表显示：头像（姓名首字）+ 姓名 + 电话、当前余额、累计充值、累计消费
- **表头可点排序**（会员 / 余额 / 累计充值 / 累计消费）

### 充值档位（充多少送多少）

会员页顶部设置，**一行一个档位，数量不限**：

```
🎁 充值档位              充值时自动带出赠送金额      [+ 添加档位]
档位     充值        赠送        到账
 1      $[500]     $[100]     $600.00      [✕]
 2      $[200]     $[ 30]     $230.00      [✕]
```

充值弹窗里：

- **一排快捷按钮**（点一下自动填金额和赠送）
- **输金额自动带出赠送**（手动改过赠送后不会被覆盖）
- 可指定「**充值提成归谁**」（默认归充值那一刻在上班的人）

### 充值可以混着付

- 收款明细支持现金 / 刷卡 / 人民币混着付，明细合计必须等于实付金额才能提交
- **充值不能用会员扣款**
- 到账金额 = 实付 ＋ 赠送（和付款方式无关）

### 提成

- 充值提成 **2%**（按实付金额算，赠送不算）
- 默认归**充值那一刻在上班的人**；也可以在充值弹窗里指定归谁
- 当时没人在上班 / 归错人 → 工资页有「**补分配充值提成**」弹窗

### 扣款 / 余额调整

| 按钮 | 作用 |
|---|---|
| **扣款** | 从余额扣（余额不足时扣完归零，差额另付） |
| **调整** | 手动修正记错的账：选「增加 / 减少」+ 金额 + **必填原因** |

> 「调整」不算充值也不算消费，不影响营业额，但会写进交易明细。

### 交易明细

- 可按会员筛选（点「明细」/「显示全部」切换）
- 每笔可以 **修改这条流水 / 删除这条**（软删除，数据留痕）
- **改/删流水后余额自动顺着整条流水重算**
- 显示：时间、会员、类型（充值 / 扣款 / 余额调整）、实付、到账 / 扣款、余额、备注

> **多设备同时扣同一个会员的钱不会算错**：流水是「一行一笔追加」，两台设备各写各的，
> 余额由云端按整条流水重新累加得出，等价于事务（带三重把关，见 [同步](#sync)）。

## 🕐 员工打卡

### 上班打卡

每张员工卡上有一个 **开始时间** 输入框（未上班时才显示）：

- **员工可以自己填开始时间**，不填就按点按钮的当前时间
- 输入时自动补冒号（敲 `0830` → `08:30`）
- 填的时间如果早于「营业日起算」，记录会算到**前一天**

### 下班打卡 / 手动补录

- **下班打卡**：按当前时间下班，自动算时长
- **+ 手动补录**：日期、上班、下班都能自己填
- 时长按分钟算，**跨零点自动 +24 小时**（23:30→01:30 = 2 小时）
- **有人上班打卡时，自动给今天还在上班的其他人打下班**（防止忘下班；只收今天的班）

### 班次（白班 / 晚班）

- **自动按分界点拆**：默认「晚班判定时间」`21:00` —— 21:00 前的小时算白班、之后算晚班（同一晚拆成两段）
- 打卡记录里每条可以**单独指定**：自动 / 白班 / 晚班
- 时薪：白班 `$16/小时`、晚班 `$18/小时`（都可改，在工资汇总面板里）

### 忙日加成

- 当天营业额超过 **`$800`** → 员工时薪 **+$1/小时**（自动判定）
- 营业额口径 = 台费 + 罚款 + 零食（含挂桌）+ 鸭嘴兽，**不含充值**
- 每条打卡可以手动强制 `是 / 否 / 自动`（比如客人少但确实很忙）

### 工资汇总（默认收起）

点员工列表右上角的 **💰 工资汇总** 展开（按钮变成「💰 收起工资汇总」）。

- 可切换 **按月 / 按周（周一到周日）**
- 每人一行：白班小时 × 时薪 + 晚班小时 × 时薪 + 忙日加成 + 充值提成 = 工资，底部合计
- 打卡下班、编辑、删除、改班次、补录、改时薪 → 汇总**立即刷新**

### 员工头像

- 8 个预设背景色 + 取色器自定义
- 上传头像图片（自动裁方、压到 96×96）
- 可「清除图片」回到文字头像；头像出现在员工卡、工资汇总、打卡记录三处

### 7 张卡

卡片下面一条通栏，显示「**已结 + 进行中 + 待结算**」的预估总额：

- 显示今天的预估；看历史营业日时，**如果那天还有没结的桌 / 待结算**也会显示
- **未结部分未含手续费**（手续费要看最后怎么付）

按类型分组显示，每组带图标、颜色和**小计**，底部有合计条：

## ⚙️ 全局设置

### 页面顶部

| 设置 | 默认 | 说明 |
|---|---|---|
| **每小时价格** | `16` | 所有桌台统一 |
| **手续费** | `1.2%` | 只对刷卡收，向上取整到分 |
| **汇率** | 自动 | 澳币→人民币；可手改；旁边「实时」按钮取最新 |
| **营业日起算** | `08:00` | 早于这个时间算前一天 |

**汇率细节**

<a id="sync"></a>

## ☁️ 多设备实时同步

### 同步范围

| 同步的 | 说明 |
|---|---|
| 结算记录、零食饮料、鸭嘴兽、会员流水、员工打卡 | 一行一笔，追加式 |
| 商品库存、员工名单、盘点记录、系统设置 | 整份 / 按 ID |
| **桌台状态**（计时中 / 暂停 / 待结算 / 挂桌零食 / 欠款） | 让别的设备也能看到哪张桌在打 |
| **预约**、**待结算区** | 多设备一致，删除也同步；新预约会弹窗提醒，「已确认」也同步（一台点过，别的设备不再弹） |
| 修改 / 删除 | 删除写「墓碑」，别的设备不会再把它拉回来（7 天后自动清） |

**不同步的**：本机界面偏好（字号、夜间模式）、操作日志、部分诊断设置 —— 只存本机。

### 实时 / 离线行为

- **实时**：Firebase SDK 走 WebSocket，通常 **1 秒内**同步
- **断网**：改动先写本机（localStorage），联网后自动补传；期间界面照常可用
- **WebSocket 连不上**：6 秒后自动切 **REST 轮询兜底**（小集合 15 秒、大集合约 5 分钟；页面在后台时暂停轮询）
- **切回前台**：立刻补拉一次最新数据
- **Service Worker**：网络优先（有网永远拿最新版），且**完全不拦截 Firebase 请求**（否则数据就不实时了）

### 多设备防打架

- 最近 **20 秒**内本机刚写 / 刚删的东西，不会被云端旧快照改回去
- 待结算有更保守的合并规则 + **墓碑删除**，不会「删了又回来」「一台结算完另一台还显示」
- 会员流水按「一行一笔追加 + 余额整条重算」实现等价事务：
  - 两台设备各扣 $50，两笔流水都在 → 余额从整个流水累加得出，不会算丢
  - 三重把关：累加出现负数（老会员开卡余额）不动；差 < $1 视为人工调整不动；差 ≥ $1 才用重算结果并写日志

### 同步状态怎么看

底部工具栏右侧会显示：

| 显示 | 含义 |
|---|---|
| `Firebase：实时同步 ✓` | 正常，实时 |
| `已连接（REST 轮询 15 秒 / 大表 5 分钟）` | 实时通道不通，兜底轮询中 |
| `后台暂停中` | 页面在后台，轮询暂停 |
| `还没连接` | 网络或配置问题，先检查网络 |

### 多设备使用建议

- 收银台电脑为主，手机用来移动开台 / 挂单 / 看数据，都没问题
- **同一张桌的结算 / 改时间 / 取消** 只在一台设备上做
- 两个人同时改同一条记录 = 后写的覆盖先写的（界面不会合并）
- 换设备 / 重装浏览器：打开网址会自动从云端拉全部数据，不用手动导备份

## 🔒 数据安全

### 数据存在哪

| 位置 | 说明 |
|---|---|
| **Firebase 云端**（主） | 项目 `tianhu-fd795`，Realtime Database，区域 `asia-southeast1`（新加坡） |
| **本机浏览器**（缓存） | localStorage，键名 `mahjong_timer_v4`，断网时先记这里 |

- 网页里内置了 Firebase 配置和**数据路径密钥**（`shops/<密钥>/`），打开即连、不用填
- 换一个路径密钥 = **换一套全新数据**（旧数据不会自动迁移）—— 不要随便改
- 网页文件本身**不含 Google 密码 / GitHub token**

### 风险（要知道）

1. **Firebase 规则目前允许匿名读写**：拿到网址 + 路径密钥的人可以读写数据。
   **安全靠「网址不外传」** —— 别发群、别发朋友圈、别放进公开仓库。
   要收紧需要加 Firebase Auth 或访问口令（还没做）。
2. **没有权限控制**：任何人都能改价格、删记录；操作日志只在本机，查不到是谁。
3. **本机缓存有上限**：浏览器给每个网站约 10MB，按每条约 467 字节算，**约 2 万条**会存不下
   （安全线 5000 条内很流畅）。云端不限制，但本机缓存满了会存不进去。
   以前有「本机保留 1 年 / 自动归档」，Firebase 版已隐藏（云端数据会被同步回来，归档没意义）；
   真到上限时先下载备份，再在记录里删旧数据。

### 三条建议

1. **每天打烊下载一次备份 JSON**，放网盘 / 微信收藏 / 另一台电脑
2. 网址只发给店里的人；**不要把网址贴到公开地方或聊天群**（网址 + 页面里的密钥就等于写权限）
3. 重要改动（改价、删记录、盘点）前先瞄一眼操作日志和记录编辑入口

### 恢复方式

| 场景 | 做法 |
|---|---|
| 有备份文件 | 「备份/恢复」→ 选备份文件 → 确认导入 |
| 云端数据是全的 | 「从 Firebase 重新读取」（会覆盖本机消费记录） |
| 误删了一条记录 | 从备份文件恢复，或看导出的 Google 表格找回内容后手动补 |
| 换设备 / 清缓存 | 直接打开网址，自动从云端拉全部数据 |

<a id="release"></a>

## 🚀 发布与更新

### 一条命令

```bash
python3 工具/发布.py --check     # 只体检：版本一致性 + 构建 + 测试 + token 权限，不推送
python3 工具/发布.py             # 正式发布（体检 → 推送 → 等线上生效 → 刷 Chrome）
python3 工具/发布.py --no-ui-tests --skip-refresh   # 紧急热修（跳过 66 秒界面测试 / 不刷页面）
```

Agent 里也可以用封装好的 `mahjong_release` 工具（`mode=check` / `mode=release`）。

### 发布脚本干的 6 件事

1. **版本一致性**：只认 `mahjong-timer.html` 的 `APP_VER`；README 的「当前版本」必须与它一致
2. **重新生成 Firebase 版**，并**断言产物版本 == 源版本**（生成器锚点失效会直接失败，不会静默发旧版）
3. **构建 `部署/index.html`**，断言版本 + 检查 `sw.js` / `manifest.json` / `assets/` 都在
4. **测试门禁**：集成测试必须绿；界面测试按「已知失败清单」区分已知过时和新回归
5. **检查 GitHub token 权限**（Contents 读写）
6. **推送 GitHub Pages → 轮询线上直到真的返回新版本 → 然后才刷新本机 Chrome**

- 有**发布锁**（`备份/.发布锁`），同一时间只能一个发布；检测到别人在改源文件会中止
- 推送目标是 `charles011031/TianhuMahjong@main`，走 GitHub Contents API（本地没有 .git）
- **`README.md` 和 `版本记录.md` 会跟着一起推**：仓库首页 README 由根目录 README 自动生成，
  版本记录原样推上去，不用另外手动发
- **线上轮询最多 300 秒**，超时算失败（退出码 3）；此时不要手动刷新，先看日志

退出码：`0` 成功 / `1` 预检失败（版本、构建、测试、token、锁、并发）/ `2` 推送失败 / `3` 线上超时未生效。

### 铁律

> **推送完成 ≠ 线上生效。** 必须等 `发布.py` 确认线上返回新版本，才刷新 Chrome。
> 自己手动推的话，也要先带 `?v=时间戳` 打开网址确认版本号变了，再刷新。

### 改代码的流程

1. 改 `mahjong-timer.html`（**只改源文件**）
2. 改顶部 `APP_VER` / `APP_DATE`（页面顶部、底部都读这两个变量）
3. README 顶部「当前版本」改成同一个版本号，`版本记录.md` 补一条（`| **vX**`）
4. 相关测试跟着补/改
5. `python3 工具/发布.py`，等它报「线上已生效」（README + 版本记录会一起推上 GitHub）
6. 再刷新页面，看顶部 / 底部版本号

### 版本号规则

**主.次.修**：

| 改了什么 | 版本怎么变 |
|---|---|
| 修 bug / 微调样式 | 第三位 +1（`3.25.5` → `3.25.6`） |
| 加新功能 | 第二位 +1、第三位归零（`3.24.0` → `3.25.0`） |
| 不兼容的大改动（旧数据/备份不能直接用） | 第一位 +1、后两位归零（`2.x` → `3.0.0`） |

`工具/发布.py` 不管版本改对没改对（它只要求三处一致），**规则靠人遵守**。

<a id="limits"></a>

## ⚠️ 已知限制

1. **没有权限控制**：拿网址的人都能改价格、删记录；操作日志只在本机
2. **Firebase 规则允许匿名读写**：安全靠网址不外传，还没有 Auth / 访问口令
3. **多设备不能同时改同一条记录**：后写的覆盖先写的（会员余额靠重算兜底，其它记录没有合并）
4. **算不出利润**：没有进货成本、也没把工资算作支出，系统只有营业额
5. **本机缓存约 10MB**：记录特别多（约 2 万条）会存不下，需要备份后清理
6. **导出到 Google 表格是独立任务**：可能因授权过期 / 定时器被删而停；停了不影响记账
7. **PWA 离线有前提**：从没联网打开过的设备，第一次纯离线用不了（SDK 在 CDN 上）
8. **`网页版/` 旧 Apps Script 版已冻结**：功能停在 2026-10-13，只能当兜底

<a id="design"></a>

## 📌 一些设计决定（为什么这样做）

| 设计 | 原因 |
|---|---|
| **手续费向上取整** | 跟 Excel ROUNDUP 一致，不会因为几分钱对不上 |
| **刷卡才收手续费** | 现金 / 人民币没有通道成本 |
| **会员余额只能抵台费** | 零食是实物商品，和储值不是一回事（程序层强制） |
| **没有折扣 / 优惠功能** | 需要抹零直接改金额 |
| **删除都要点两下** | 内部系统，防手滑 |
| **零食 / 鸭嘴兽价格可改但要手填** | 价格会变，硬编码会过期 |
| **不记录进货成本** | 所以只有营业额，没有利润 |
| **待结算先停表、后收钱** | 客人走了桌子能立刻给下一桌，钱慢慢对 |
| **会员流水追加 + 余额重算** | 多设备同时扣款不丢钱，等价于事务 |

<a id="faq"></a>

## 🆘 常见问题

**Q：换手机 / 换电脑，数据还在吗？**
在。数据在 Firebase 云端，打开网址自动拉全部数据，不用导备份。

**Q：两台设备能同时记账吗？**
能，实时同步。但**同一张桌的结算 / 改时间 / 取消**只在一台设备做，否则后写的覆盖先写的。

**Q：断网了还能用吗？**
能继续记，先存本机，联网自动补传。从没联网打开过的新设备第一次不能纯离线用。

**Q：客人打完直接走了怎么办？**
先「⏹ 结束计时」→「收进待结算」空出桌子 → 回头再「💰 结算收费」。见 [自助场景](#selfservice)。

**Q：会员余额能付零食吗？**
不能，只能抵台费（含上次未付）。整单结算时零食那部分会自动拆出来另收。

**Q：当前显示「REST 轮询」是不是坏了？**
不是坏，是 WebSocket 不通时的兜底：小集合 15 秒、大集合约 5 分钟，仍能同步，只是不实时。

**Q：库存对不上怎么办？**
用卡片上的「盘点」按实际数量校准，会留盘点记录。

**Q：账记错了能改吗？**
能。结算记录、零食记录、鸭嘴兽记录、会员流水都有编辑；改时间会重算台费，会员余额会自动对账。

**Q：为什么我改了文件，手机上还是旧版？**
线上是 GitHub Pages 的 `部署/index.html`，要跑 `工具/发布.py` 发布，并且**等线上返回新版本**再刷新。

**Q：数据会不会丢？**
云端有实时库 + 本机缓存 + 你下载的备份。最稳的做法是**每天打烊下载一次备份 JSON**。

<a id="tech"></a>

## 🛠 技术说明

- **单文件 HTML**，纯原生 JS（IIFE + `"use strict"`），无框架、无构建步骤
- **同步**：Firebase Realtime Database，SDK 10.12.2（compat，gstatic CDN）；WebSocket 主通道 + REST 轮询兜底
- **托管**：GitHub Pages（静态）；PWA：`manifest.json` + `sw.js`（网络优先，只缓存同源 GET）
- **数据格式**：本机 JSON 存 localStorage（键名 `mahjong_timer_v4`），云端按集合分节点存
- **计费**：分钟向上取整；台费 / 手续费向上取整到分；营业日按 `08:00` 切分
- **兼容**：Chrome / Edge / Safari 现代版本；手机横竖屏都适配
- **汇率接口**：`https://open.er-api.com/v6/latest/AUD`（市场价 × 加点）
- **数字输入框**：全局禁用滚轮改值、上下箭头步进，只能键盘输入
- **发布**：GitHub Contents API 推送（`charles011031/TianhuMahjong@main`），线上轮询 `APP_VER` 确认生效
